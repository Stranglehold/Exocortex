## Refactoring Goals

### 1. **Separation of Concerns** 🎯
Currently all logic is in one file. Plan to split into:
```python
memory_classifier/
├── __init__.py              # Main extension hook (MemoryClassifier class)
├── classifiers.py           # Strategy implementations for 5 axes
├── lineage.py               # Memory ancestry tracking & versioning
├── conflict_resolver.py     # Semantic contradiction detection
├── maintenance.py          # Archival lifecycle management
└── config.py              # Configuration schema and validation
```

### 2. **Strategy Pattern for Classifiers** 🔧
The five classification axes are currently procedural functions with similar signatures but different logic. Convert to a **Strategy pattern**:

```python
from abc import ABC, abstractmethod

class Classifier(ABC):
    @abstractmethod
    def classify(self, text: str, metadata: dict, config: dict) -> str: ... 

class ValidityClassifier(Classifier): ...
class RelevanceClassifier(Classifier): ...  # etc.
```

Benefits:
- Testable in isolation (pure functions)
- Easy to add new classification axes
- Clear single-responsibility per class

### 3. **Configuration Management** 📋
Currently uses `DEFAULT_CONFIG` dict with loose key access (`config.get("key", default)`). Plan:
- Use Pydantic or dataclass for typed config validation
- Centralize all magic strings (e.g., `"_mem_cls"`, `"_mem_lin"`) as constants
- Validate config on load, fail fast if keys missing/invalid

### 4. **Error Handling Improvements** 🛡️
Current code uses bare `except:` in many places with silent `pass`:
```python
try: ... except Exception: pass  # Debugging nightmare!
```
Plan:
- Create custom exception hierarchy (`MemoryClassificationError`, `ConflictResolutionError`)
- Log errors to agent context (not silent failures)
- Graceful degradation where appropriate, but alert on critical paths

### 5. **Type Hints & Documentation** 📝
- Add full type annotations throughout
- Expand docstrings with usage examples for each classifier strategy
- Document the five classification axes in a table format within code comments

### 6. **Lineage as First-Class Object** 🌳
Currently lineage is a dict manipulated inline. Plan:
```python
@dataclass
class MemoryLineage:
    created_at: datetime
    created_by_role: str | None
    superseded_by: str | None
    supersedes: str | None
    access_count: int = 0
```
Benefits: Clear API, immutable after creation (except for updates), easier to query.

### 7. **Conflict Resolution Refactoring** ⚖️
Current `_detect_conflicts` mixes:
- Similarity search (FAISS vector operations)
- Semantic analysis (regex patterns, negation detection)
- Business logic (priority rules)

Plan to separate:
1. `CandidateRetriever`: Fetches similar memories from FAISS
2. `ContradictionAnalyzer`: Pure semantic analysis functions
3. `ConflictResolver`: Decides winner/loser based on priority hierarchy

### 8. **Testing Hooks** 🧪
- Extract pure functions (remove side effects from classification logic)
- Mock the FAISS database interface for unit tests
- Create fixtures for test memories covering edge cases
