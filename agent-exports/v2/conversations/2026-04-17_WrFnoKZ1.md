# PEP 695 Type Parameter Syntax: Design Principles & Rationale

## The Problem with the Old Syntax

Python's original approach to generics (introduced in Python 3.5) felt "bolted on" to the language:

```python
# Old style - requires imports, global definitions, and boilerplate
from typing import TypeVar, Generic, List

T = TypeVar('T')
U = TypeVar('U')

class Container(Generic[T]):  # Must inherit from Generic
    def __init__(self, value: T) -> None:
        self.value = value

def identity(x: T) -> T:  # TypeVar defined globally but used locally
    return x
```

**Key Issues:**
1. **Scoping confusion**: `TypeVar` objects allocated globally but only had semantic meaning within specific generic contexts
2. **Misuse of type aliases**: Developers could write `MyList = List` (missing `[T]`) and get implied `Any` values
3. **Cognitive overhead**: Beginners forced to understand variance (`covariant`, `contravariant`) for simple tasks
4. **Inconsistent with specialization syntax**: Declaration used `TypeVar()` but specialization used `[]`

---

## Design Principles Behind the New Syntax

### 1. **Consistency with Python Conventions**

The new syntax uses square brackets `[]` — matching Python's existing use of square brackets for explicit specialization:

```python
# Declaration and specialization now use the same syntax
list[int]    # Specialization (old style still works)
list[T]      # Type parameter declaration (new PEP 695 style)
```

### 2. **Natural Declaration Location**

Type parameters declared where they're actually used — at the natural place within class, function, or type alias declarations:

```python
# New Python 3.12 syntax - no imports needed for simple cases
class Container[T]:       # T is scoped to this class
    def __init__(self, value: T) -> None:
        self.value = value

def identity[T](x: T) -> T:  # T is scoped to this function
    return x
```

### 3. **Simplicity and Accessibility**

> "Variance is an advanced topic that many developers find confusing, so we want to eliminate the need to understand this concept for most Python developers." — PEP 695

The design infers variance automatically (like most modern languages), reducing cognitive load.

### 4. **Alignment with Other Languages**

A survey in Appendix A showed how other languages handle type parameters. The chosen syntax aligns developer expectations across:
- Java: `class MyClass<T>`
- C#: `class MyClass<T>`
- Rust: `struct MyClass<T>`

## Key Design Decisions and Why Alternatives Were Rejected

### ❌ **Angle Brackets `<T>`** — REJECTED

```python
class Container<T>:  # Not chosen
```

**Why rejected:**
- Angle brackets are not "paired" by Python's scanner, causing line break issues requiring escape sequences
- Inconsistent with existing square bracket usage for specialization (`list[int]`)

### ❌ **Prefix Clause `using T`** — REJECTED

```python
using T:
def identity(x: T) -> T:  # Not chosen
    return x
```

**Why rejected:**
- Scoping rules were less clear
- Did not interact well with Python decorators (very common pattern)

### ❌ **Explicit Variance Specification** — REJECTED

```python
class Container[covariant T]:  # Not chosen
```

**Why rejected:**
- Variance can be inferred by the type checker (as most modern languages do)
- It's an advanced concept that confuses developers unnecessarily

### ✅ **Colon-Based Bounds `T: int`** — SELECTED

```python
def process[T: int](value: T) -> str:
    return str(value * 2)
```

**Why chosen:**
- Consistent with many other programming languages
- "Heavily preferred by a cross section of Python developers who were surveyed"

## Additional Features Enabled by the Design

### Type Aliases Get First-Class Treatment

```python
# Before: had to use typing.NewType or workarounds
type MyList[T] = list[T]    # Generic type alias

type Number = int | float   # Non-generic alias
```

### Lazy Evaluation of Bounds and Constraints

Enables recursive and mutually recursive type aliases without quote escapes:

```python
type TreeNode[T] = {
    "value": T,
    "children": list[TreeNode[T]]  # Recursive reference works naturally
}
