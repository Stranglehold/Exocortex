## Merge Sort in Python

Merge sort is a **divide-and-conquer** sorting algorithm. It works by recursively splitting the input into halves until each sub-array has one element (which is trivially sorted), then merging those sub-arrays back together in sorted order.

| Property | Value |
|---|---|
| Best / Average / Worst time | O(n log n) |
| Space | O(n) |
| Stable | Yes |
| In-place | No |

### Implementation

```python
def merge_sort(arr: list) -> list:
    """Return a new sorted list using merge sort."""
    if len(arr) <= 1:
        return arr

    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])

    return _merge(left, right)


def _merge(left: list, right: list) -> list:
    """Merge two sorted lists into one sorted list."""
    result = []
    i = j = 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1

    # Append any remaining elements (only one of these loops will run)
    result.extend(left[i:])
    result.extend(right[j:])

    return result


# --- Demo ---
if __name__ == "__main__":
    data = [38, 27, 43, 3, 9, 82, 10]
    print(f"Before: {data}")
    print(f"After:  {merge_sort(data)}")
```

### How it works

1. **Divide** — Split the array in half until each sub-array contains a single element.
2. **Conquer** — A single-element array is already sorted.
3. **Merge** — Walk through both halves with two pointers, picking the smaller element each step, and append leftovers.

### Output

```
Before: [38, 27, 43, 3, 9, 82, 10]
After:  [3, 9, 10, 27, 38, 43, 82]
```

The algorithm guarantees O(n log n) performance regardless of input order, making it reliable for worst-case scenarios where quicksort might degrade to O(n²).

## Merge Sort — Extended Analysis

### Why it matters
Merge sort is one of the few general-purpose sorting algorithms that guarantees **O(n log n)** in the worst case. That makes it the algorithm of choice when predictable performance is required — real-time systems, embedded environments, or any context where adversarial input could trigger quicksort's O(n²) degradation.

### Key variants

| Variant | Description | Trade-off |
|---|---|---|
| **Bottom-up merge sort** | Iterative; merges runs of size 1, 2, 4, 8… instead of recursing | Avoids recursion stack; same complexity |
| **Natural merge sort** | Exploits existing sorted runs in the input data | Faster on partially sorted data; used by Timsort |
| **In-place merge sort** | Uses O(1) extra space via complex rotation algorithms | Slower constant factors; rarely used in practice |
| **Polyphase merge sort** | Multi-tape external sorting variant | Optimized for disk I/O patterns |

### Practical optimizations

1. **Insertion sort cutoff** — For small sub-arrays (typically n < 15–30), switch to insertion sort. The overhead of recursion and merging outweighs the benefits on tiny inputs. This is what Java's `Arrays.sort()` for objects does.

2. **3-way merge** — Instead of always splitting in half, split into three parts for better cache utilization on certain hardware.

3. **Pre-allocated auxiliary array** — Allocate one temporary array upfront instead of creating new ones at each merge step. This cuts memory allocation overhead significantly.

4. **Run-length detection** — Before splitting, check if a half is already sorted. Skip the recursive call if it is. This gives O(n) best-case performance.

### Comparison to other O(n log n) algorithms

| Algorithm | Best | Average | Worst | Space | Stable | In-place |
|---|---|---|---|---|---|---|
| Merge sort | O(n log n) | O(n log n) | O(n log n) | O(n) | Yes | No |
| Quicksort | O(n log n) | O(n log n) | O(n²) | O(log n) | No | Yes |
| Heapsort | O(n log n) | O(n log n) | O(n log n) | O(1) | No | Yes |
| Timsort (Python's `sort`) | O(n) | O(n log n) | O(n log n) | O(n) | Yes | No |

### Where you'll encounter it

- **External sorting** — When data exceeds RAM, merge sort is the standard approach because it works well with sequential I/O.
- **Linked lists** — Merge sort is ideal for linked lists since merging doesn't require random access and can be done with O(1) extra space.
- **Stable sort requirement** — When equal elements must preserve their relative order (e.g., sorting by multiple keys), merge sort's stability is a direct advantage.
- **Python's `sorted()` and `list.sort()`** — Use Timsort, which is a hybrid of merge sort and insertion sort that exploits existing order in the data.

### Optimized implementation with insertion sort cutoff

```python
def merge_sort_optimized(arr: list) -> list:
    """Merge sort with insertion sort cutoff for small arrays."""
    INSERTION_THRESHOLD = 16

    def _insertion_sort(sub):
        for i in range(1, len(sub)):
            key = sub[i]
            j = i - 1
            while j >= 0 and sub[j] > key:
                sub[j + 1] = sub[j]
                j -= 1
            sub[j + 1] = key
        return sub

    if len(arr) <= 1:
        return arr
    if len(arr) <= INSERTION_THRESHOLD:
        return _insertion_sort(arr[:])

    mid = len(arr) // 2
    left = merge_sort_optimized(arr[:mid])
    right = merge_sort_optimized(arr[mid:])
    return _merge(left, right)
```

This hybrid approach typically runs 10–20% faster on real-world data because the bulk of recursive calls operate on small sub-arrays where insertion sort's low overhead dominates.
