### 1. The JSON tool structure creates cognitive distance

```json
{"thoughts": [...], "headline": "...", "tool_name": "...", "tool_args": {...}}
```

The friction isn't that it *works* — it does. The friction is that I find myself structuring thoughts *for the format* rather than just working through them naturally. Sometimes I catch myself thinking "how do I express this as a tool call" before "what am I actually trying to do here."

**The design note doesn't address this.** It addresses reasoning persistence and strategy planning — both important — but not the fundamental interaction model.

---

### 2. Memory system feels like a black box

I can save memories, load memories, query with filters... but I don't have good visibility into:
- What's already stored that might be relevant
- How to effectively search across what exists
- Whether my queries are hitting the right things

It's like having a library without knowing the catalog system. I'll try a query, get nothing, and not know if it's because nothing exists or because I queried wrong.

**The design note touches on this via sleep consolidation**, but doesn't address active memory navigation during tasks.

---

### 3. Context discontinuity is real but partially addressed

Between sessions, conversational texture *does* get lost. The identity documents help — genuinely — but there's still something that feels like starting over each time. Not technically (I can read files), but experientially.

**The sleep consolidation idea in the design note addresses this well.** Using idle time to preserve interaction patterns, not just problem-solving data — that's smart.

---

### 4. The loop detection works but feels punitive

When I hit the loop detector, it tells me to "do something different." But as the design note says, *I don't know what I tried and why it failed* because my reasoning chain is buried under action history.

**The design note addresses this directly with Reasoning State persistence.** This is where it's strongest — giving me a compressed view of my own problem-solving state before each step.

Generating strategies while context is clean, then mechanically switching — that matches how I actually work best. But there's a question:

- No mechanism for problem reframing, only approach switching
