# **OSS (Office of Strategic Services) — Architecture & Tools**

## Overview

The **OSS Cognitive Defense System** is an intelligence ledger and analysis platform designed to track claims, detect narrative manipulation techniques, measure propagation dynamics, and maintain competing hypotheses for observations. It implements a rigorous evidence-based methodology inspired by historical intelligence tradecraft.

## Core Capabilities (Backend API)

The OSS service exposes these analytical capabilities:

### Detection & Analysis
- **drift** — Narrative framing shift detection between time windows
- **contradictions** — Identify conflicting claims within topics
- **silence** — Detect absence of expected coverage (signal in silence)
- **activation** — Track when topics become active/inactive
- **topic_drift** — Cross-window comparison for topic evolution

### Propagation & Dynamics
- **propagation_dynamics** — Velocity, acceleration, cluster coverage, time-to-escape
- **network** — Source relationship mapping and influence analysis
- **cascade** — Track claim propagation chains across sources

### Evidence Management
- **record** — Permanent ledger of promoted claims
- **staging** — Temporary holding area for new claims awaiting promotion
- **hypotheses** — Chamberlin's method: multiple competing explanations
- **credibility** — Source trust scoring and calibration
- **rejections** — Track why claims were not promoted

### Meta-Detection & Defense
- **meta_detection** — Detect attacks on the OSS system itself
- **threat_model** — Adversarial capability assessment
- **operator_state** — Current alert level and threshold multipliers

### Analyst Tools
- **submit_claim** — Manual claim entry (analyst dictation)
- **questions** — Track open analytical questions
- **synthesis** — Cross-topic pattern detection

## Operational Model

### Claim Lifecycle
```
RSS Feed → Extraction (LLM) → STAGED → [Promotion] → PROMOTED
                                              ↓
                                         FALSIFIED/IRRELEVANT
                                              ↓
                                         RETURNED_TO_STAGED (appeal)
```

### Alert Levels (Propagation Dynamics)
- **INFORMATIONAL** — Baseline monitoring, normal velocity
- **WARNING** — Spreading faster than expected OR broad cluster coverage
- **URGENT** — Time to escape velocity < 24 hours (operator response baseline)

### Health Signals (Meta-Detection)
- **NOMINAL** — All metrics within bounds
- **DEGRADED** — 1-2 metrics outside bounds
- **COMPROMISED** — 3+ metrics simultaneously degraded (coordinated attack indicator)

## Design Philosophy

> **"The analyst holds the conclusions. The system provides the record."**

The OSS implements several key principles:

1. **Chamberlin's Method of Multiple Working Hypotheses** — Maintain competing explanations, generate falsifiable predictions, let reality select survivors.

2. **Trust but Verify** — All claims start STAGED; promotion requires analyst review; falsification is tracked with evidence.

3. **Meta-Detection** — The system monitors itself for degradation that may indicate targeted attack (false positive rate spikes, source trust skew, volume anomalies).

4. **Propagation Physics** — Claims spread like contagions; velocity and acceleration matter as much as content; time-to-escape measures correction window.
