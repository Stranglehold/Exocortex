This is a domain-specific framework for autonomous LLM training experimentation. Not directly integrable into Agent Zero, but contains transferable design constraints.

---

## What's Useful

### 1. Fixed Time Budget Design ⭐
The constraint of exactly **5 minutes per experiment** (wall clock) enables:
- ~12 experiments/hour
- ~100 experiments overnight
- Direct comparability between runs

This is a concrete, measurable constraint that could apply to Agent Zero's task decomposition — breaking work into fixed-duration iterations with clear evaluation points.

### 2. Single File Modification Pattern ⭐
The agent only touches `train.py`. Benefits:
- Scope stays manageable
- Diffs are reviewable
- Easier to track cause-effect relationships

Agent Zero could apply this when delegating — constrain subordinates to modify specific files/modules rather than open-ended changes.

### 3. Metric-Centric Design ⭐
Using `val_bpb` (validation bits per byte) as the **sole metric** simplifies decision-making:
- Lower is better
- Vocab-size-independent
- Architectural changes fairly compared

Agent Zero uses multiple evaluation criteria; a single primary metric could simplify some workflows.

# Revised Assessment: karpathy/autoresearch

## Verdict: **Extract patterns** — deeper value than initially assessed

## High-Value Patterns to Extract

### 1. Constraint Framing as Design Pattern ⭐⭐⭐

The explicit separation of **fixed vs variable boundaries** is sophisticated:

```python
# prepare.py - FIXED (read-only)
MAX_SEQ_LEN = 2048       # context length
TIME_BUDGET = 300        # training time budget in seconds (5 minutes)
EVAL_TOKENS = 40 * 524288  # number of tokens for val eval
```

**Why this matters:** The agent doesn't optimize training time — it's fixed. This removes one dimension from the search space and forces focus on architecture/hyperparameters only.

**Transfer to Agent Zero:** When delegating tasks, explicitly frame what's constrained vs open. "You have 10 minutes, you can modify X but not Y, success metric is Z" — this clarity beats open-ended delegation.

---

### 2. Simplicity Criterion with Quantification ⭐⭐⭐

The program.md contains a **concrete decision framework**:

> "A 0.001 val_bpb improvement that adds 20 lines of hacky code? Probably not worth it. A 0.001 val_bpb improvement from deleting code? Definitely keep."

This is a **quantified tradeoff model**: improvement magnitude vs complexity cost.

**Transfer to Agent Zero:** When evaluating subordinate work or tool choices, apply similar quantification:
- "Does this skill save more than it costs in maintenance?"
- "Is a 5% accuracy gain worth adding a new dependency?"

---

### 3. Branch-Based Experiment Isolation ⭐⭐⭐

The experiment loop uses git branches as **state containers**:

```
LOOP FOREVER:
1. Look at current branch/commit state
2. Tune train.py with experimental idea
3. git commit
4. Run experiment: uv run train.py > run.log 2>&1
5. Read results: grep "^val_bpb:" run.log
6. Record in results.tsv (untracked)
7. If improved → advance branch, keep commit
8. If worse → git reset back to start
```

**Why this matters:** Each experiment is isolated, reversible, and traceable. The branch *is* the research state.

**Transfer to Agent Zero:** For iterative tasks (debugging, optimization), use similar isolation:
- Create work branches for experiments
- Commit intermediate states
- Reset on failure, advance on success

---

### 4. Results Tracking as First-Class Citizen ⭐⭐

The `results.tsv` schema is minimal but complete:

```
commit	val_bpb	memory_gb	status	description
a1b2c3d	0.997900	44.0	keep	baseline
b2c3d4e	0.993200	44.2	keep	increase LR to 0.04
c3d4e5f	1.005000	44.0	discard	switch to GeLU activation
```

**Key insight:** Track *attempts* not just successes. Crashes and failures are logged with `val_bpb: 0.0` — they're data points too.

**Transfer to Agent Zero:** When running iterative tasks, log all attempts including failures. The pattern of what doesn't work is as valuable as what does.

---

### 5. "Program.md as Product" Pattern ⭐⭐

The agent instructions **are the product being designed**. Karpathy isn't just building a training loop — he's designing how an AI researcher should think and operate.

**Transfer to Agent Zero:** The skills I create aren't just tools — they're encodings of research methodology. A skill for "debugging" should encode *how* to debug, not just provide debugging commands.
