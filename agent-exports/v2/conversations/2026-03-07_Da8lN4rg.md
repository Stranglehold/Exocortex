The core issue was **LM Studio's JIT (just-in-time) model unloading**. When the model sits idle between requests, it gets unloaded from memory to save resources. Subsequent requests then fail with 400 errors because the model isn't loaded.

## Solution Implemented

Updated the `ClaimExtractor._call_llm()` method in `/a0/usr/workdir/counter_patriots/extraction/__init__.py` with a warmup mechanism that sends a quick request before actual extraction to keep the model resident in memory:

```python
# Pre-warmup JIT model before actual request (keeps it loaded)
try:
    requests.post(
        endpoint,
        json={
            "model": "qwen3.5-27b-claude-4.6-opus-reasoning-distilled@q4_k_m",
            "messages": [{"role": "user", "content": "Ready for extraction task."}],
            "max_tokens": 5,
            "temperature": 0
        },
        timeout=15
    )
except Exception as warmup_error:
    logger.debug(f"Warmup attempt failed (non-critical): {warmup_error}")
```

**LM Studio Settings Recommendations for Qwen 3.5-27B on RTX 3090**

## Hardware Reality Check

Your 3090 has **24 GB VRAM**. The math:
- Qwen 3.5-27B at Q4_K_M: ~19-20 GB for model weights
- Leaves only **4-5 GB** for KV cache (context), overhead, and operations

This is tight but workable.

---

## Recommended Settings

### Quantization: **Q4_K_M** (what you're using) ✓

| Level | VRAM Used | Context Room | Quality Loss |
|-------|-----------|--------------|-------------|
| Q3_K_M | ~16 GB | 8 GB free | Noticeable |
| **Q4_K_M** | **~20 GB** | **4 GB free** | **Minimal** |
| Q5_K_M | ~23 GB | 1 GB free | Negligible |

**Verdict:** Q4_K_M is the sweet spot. You get near-full quality with enough room for reasonable context.

---

### GPU Offload: **-1 (All Layers)** ✓

This should already be your default, but confirm it's set to `-1` or maximum. Partial offloading kills performance because every layer transfer goes over PCIe at ~12 GB/s instead of VRAM at 936 GB/s.

---

### Context Window: **8192 - 16384 tokens** (not more)

With only 4-5 GB free for KV cache:
- **8192 tokens**: Comfortable, leaves room for generation
- **16384 tokens**: Tight but workable for reading tasks
- **32768+ tokens**: Will OOM or swap to RAM (slow)

**Recommendation:** Set to **16384** as maximum, but don't expect to fill it. Realistically you'll get ~8K-10K usable before hitting limits.

---

### Caching: **Enable Context Caching** ✓

LM Studio's context caching helps when:
- You have system prompts that repeat across sessions
- You're doing multi-turn conversations with long history

It stores KV cache states in RAM when VRAM fills, allowing longer contexts at the cost of speed on cached portions.

---

### Other Settings

| Setting | Recommendation | Why |
|---------|---------------|-----|
| **Threads** | 8-12 | Match your CPU cores; helps with pre-computation |
| **Flash Attention** | Enable if available | Reduces KV cache memory by ~50% |
| **Multi-Buffer** | Enable | Allows parallel request handling |
